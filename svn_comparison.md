# Git vs SVN

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?
В Git ветка — это просто файл-указатель (41 байт) на коммит. Создание ветки ничего не копирует и происходит мгновенно и локально, а переключение лишь меняет файлы рабочей копии по снимкам из локальной базы.
В SVN ветка — это копия каталога на сервере (`svn copy trunk branches/x`). Сервер делает её «дешёвой копией», но это всё равно сетевая операция с отдельной ревизией, а работа в ветке требует отдельной рабочей копии или `svn switch`. Слияние веток в SVN исторически было сложным, поэтому ветки там создают редко.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?
Нет. SVN — централизованная система: история хранится только на центральном сервере, а коммит — это запись новой ревизии на сервер. Без связи можно лишь редактировать файлы и смотреть `svn diff` / `svn status` относительно последней скачанной версии. В Git коммит пишется в локальный репозиторий, а на сервер отправляется потом командой `git push`.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?
- Большие бинарные файлы (игровые ассеты, CAD-модели, видео): SVN не заставляет каждого скачивать всю историю, есть блокировки файлов (`svn lock`), чтобы двое не правили один бинарник.
- Огромные монорепозитории, где нужен частичный checkout только одного подкаталога.
- Строгий централизованный контроль доступа (права на уровне каталогов) и линейная нумерация ревизий — это ценят в госсекторе и банках.
- Legacy-проекты, где миграция на Git стоит дороже, чем поддержка SVN.
